# Как устроен md-slides

## Общая схема

```text
talk.md ──► deck.py ──► markdown.py + inline.py + highlight.py ──► render.py ──► talk.html
            (слайды,     (Markdown → HTML для каждого слайда)       (шаблон +       (CSS + JS
             заметки,                                                 CSS + JS)       внутри)
             директивы)
                          cli.py: build / serve / init / outline
                          server.py + watch.py: живой предпросмотр
```

Python-часть работает **только на этапе сборки**. Результат — статическая страница, всё поведение (навигация, фрагменты, докладчик) реализовано в `assets/app.js`.

## Модули

### `deck.py`: структура презентации
1. **Front matter.** Если файл начинается с `---` и все строки до следующего `---` имеют вид `ключ: значение`, это метаданные. Иначе первый `---` считается обычным разделителем слайдов. Так файл, который начинается со слайда, не ломается.
2. **Деление на слайды** по строке `---`. Парсер помнит, открыт ли блок кода (```` ``` ```` или `~~~`), поэтому `---` внутри кода (например, в YAML) не режет слайд.
3. **Заметки и директивы.** Строка `Note:` переключает сбор строк в заметки. HTML-комментарии с известными ключами (`class`, `fragments`, `background`, `color`, `id`) превращаются в директивы, неизвестные остаются текстом.

### `markdown.py`: блочный парсер
Классический построчный разбор: по первой строке определяется тип блока (код, заголовок, линия, цитата, список, таблица, абзац), блок «забирает» свои строки, затем парсер идёт дальше.

- **Рекурсия.** Содержимое цитаты и пункта списка разбирается тем же методом `_blocks`, поэтому внутри них работают любые блоки: вложенные списки, код, цитаты.
- **Тесные и свободные списки.** Если между пунктами нет пустых строк, текст пункта не оборачивается в `<p>`, как в GitHub.
- **Ленивые продолжения.** Строка без отступа после текста пункта или цитаты продолжает абзац.
- **Таблицы.** Строка с `|`, за которой следует разделитель `|:--|:-:|`. Ячейки делятся с учётом `\|` и кода в обратных кавычках. Короткие строки дополняются пустыми ячейками.

### `inline.py`: строчная разметка
Главный приём — **плейсхолдеры**. Готовые фрагменты (код, ссылки, картинки, экранированные символы) сразу превращаются в HTML и прячутся за маркерами `\x00N\x00`. Затем весь оставшийся текст экранируется, к нему применяются регулярки для `**`, `*`, `~~`, и в конце маркеры подставляются обратно. Это даёт две гарантии:
- разметка внутри `кода` не срабатывает;
- пользовательский текст **всегда** экранирован, «сырой» HTML в результат не попадает.

Ссылки проверяются функцией `is_safe_url`: разрешены `http(s)`, `mailto`, относительные пути, якоря и `data:image/`. `javascript:` и подобные схемы выводятся как текст.

### `highlight.py`: подсветка кода
Для каждого языка задан упорядоченный список правил (комментарий, строка, число, ключевое слово…). Правила собираются в одно регулярное выражение с именованными группами, и код проходится за один проход. Порядок правил важен: комментарии и строки идут первыми, поэтому `"for"` внутри строки не подсвечивается как ключевое слово. Это не полноценный лексер, но для слайдов этого хватает, и не нужен Pygments.

### `render.py`: сборка страницы
- Подставляет в `template.html` CSS, JS, слайды и JSON-конфиг. Подстановка `{{ключ}}` выполняется **за один проход**, поэтому текст `{{css}}` в слайде не превратится в стили.
- JSON-конфиг экранирует `</`, чтобы заголовок вида `</script>` не закрыл тег скрипта.
- Значения директив проверяются белым списком символов, классы — по шаблону `[\w-]+`. Некорректные значения не ломают сборку, а попадают в `warnings`, и CLI их выводит.
- `--embed-images` подменяет `src` картинок на `data:` URI через функцию-резолвер, которая передаётся в парсер. Сам парсер о файлах ничего не знает.

### `server.py` и `watch.py`: живой предпросмотр
- `FileWatcher` раз в 0,5 с проверяет `mtime` и размер файла. Опрос выбран вместо inotify/watchdog, потому что одинаково работает на всех ОС и не требует зависимостей. Метод `check()` вынесен отдельно, чтобы тесты могли выполнить один шаг без потоков и `sleep`.
- `PreviewState` хранит текущий HTML и счётчик версий под замком. Если сборка падает, в браузер отдаётся страница с ошибкой, которая тоже перезагружается сама, когда ошибку исправят.
- Страница в режиме `serve` раз в секунду запрашивает `/__version` и вызывает `location.reload()` при изменении. Это проще WebSocket и работает на стандартном `http.server`.
- Статика отдаётся только из папки исходника. Путь проверяется через `resolve()` и `parents`, поэтому `../../etc/passwd` получает 404. Сервер слушает только `127.0.0.1`.

### `assets/app.js`: показ
- **Масштабирование.** Слайд всегда имеет размер 1280×720 логических пикселей, а `transform: scale()` вписывает его в окно. Поэтому вёрстка выглядит одинаково на любом экране и при печати.
- **Фрагменты.** Состояние — сколько элементов `.fragment` на текущем слайде видимо. «Вперёд» сначала показывает следующий фрагмент, а потом листает. «Назад» на предыдущий слайд открывает его со всеми фрагментами, как в PowerPoint.
- **Докладчик и обзор** используют клоны слайдов (`cloneNode`) в уменьшенном масштабе, так что вторая копия разметки не нужна.
- **Тема** запоминается в `localStorage`. Ключ включает тему сборки, чтобы пересборка с другой темой не перебивалась старым выбором. Ошибки хранилища (приватный режим) перехватываются.
- `window.mdSlides` — небольшой API для отладки и браузерных тестов.

## Ключевые решения

| Решение | Почему |
|---|---|
| Свой парсер Markdown вместо `markdown`/`mistune` | Ноль зависимостей; полный контроль над экранированием и фрагментами; хорошая демонстрация навыков в портфолио |
| Один HTML-файл | Презентацию можно отправить письмом или открыть с флешки без интернета |
| Экранирование «сырого» HTML | Безопасно открывать чужие `.md`; цена — нельзя вставить свой `<iframe>` |
| `---` только как разделитель | Это привычно (так делают reveal.js и Marp); для линии остаются `***` и `___` |
| Опрос файла вместо inotify | Кроссплатформенно и без зависимостей |
| Тесты в настоящем браузере | Логика навигации живёт в JS, и проверять её через Python-строки бессмысленно |

## Тесты

- `test_inline.py`, `test_markdown.py`, `test_highlight.py` проверяют парсер, включая XSS-случаи и граничные ситуации (незакрытый код, `|` в таблице, `snake_case`).
- `test_deck.py` проверяет front matter, разделители в коде, заметки и директивы.
- `test_render.py` проверяет сборку, темы, ошибки, встраивание картинок и защиту шаблона.
- `test_cli.py` проверяет все команды и коды возврата.
- `test_watch_server.py` проверяет наблюдатель, сервер на случайном порту, пересборку, страницу ошибки и защиту от `../`.
- `test_browser.py` проверяет навигацию, фрагменты, хэш, переход, докладчика, обзор, темы, масштаб и печать в Chromium. Во всех тестах проверяется, что в консоли нет ошибок.

## Что можно улучшить

1. **Экспорт в PDF из CLI:** `md-slides pdf talk.md` через Playwright (опциональная зависимость).
2. **Синхронизация двух окон:** докладчик на ноутбуке, слайды на проекторе через `BroadcastChannel`.
3. **Подсветка строк кода:** ```` ```python {2,4-5} ```` и пошаговая подсветка как фрагменты.
4. **Двухколоночные слайды:** директива `<!-- columns -->` с разделителем `|||`.
5. **Пользовательские темы:** `--css my.css` или `theme: ./my-theme.css` во front matter.
6. **Математика** через встраиваемый KaTeX (опционально).
7. **Сноски и определения**, ссылки-сноски `[текст][1]`.
8. **Публикация в GitHub Actions:** workflow, который собирает все `.md` из `slides/` и выкладывает на Pages.
